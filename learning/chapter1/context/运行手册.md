## 2. 环境准备

以下命令在 PowerShell 7 中运行：

```powershell
Set-Location '<clone-path>\learning\chapter1\context\code'

python -X utf8 -c "import openai, dotenv, pypdf; print('【环境检查】依赖导入成功')"
```

若当前终端不能激活 Conda，可直接通过环境名运行：

## 3. 应该运行哪个入口

| 入口 | 用途 | 是否请求模型 |
|---|---|---:|
| `main.py --help` | 查看参数 | 否 |
| `python -m pytest ...` | 验证本地裁剪逻辑和命令分流 | 否 |
| `main.py --mode interactive` | 手动切换模式、输入任务、观察轨迹 | 普通任务会请求 |
| `main.py --mode single` | 用指定模式执行一个任务 | 是 |
| `main.py --mode ablation` | 运行演示型多模式对照 | 是 |
| `run_experiment_1_1.py` | 生成带 Context Contract、API Turn 和 SHA-256 的正式证据 | 是 |
| `vis_validation.py` | 在浏览器查看 evidence | 否 |

推荐顺序：

```text
pytest
↓
interactive
↓
单个模式探测
↓
完整五模式正式实验
↓
读取 evidence
```

## 4. 五种实验模式

| 模式 | 运行层实际处理 |
|---|---|
| `full` | 保留完整历史、工具声明、工具调用和结果 |
| `no_history` | 后续轮次只保留静态前缀和原始用户任务 |
| `no_tool_results` | 保留 Tool Call，但不给模型真实 Observation |
| `no_tool_calls` | 不向模型声明工具 |
| `no_reasoning` | 保留工具调用和结果，但不把历史推理文本写回下一轮 |

模式的原理和历史结果解释不在本 README 重复维护，请看 Obsidian 主笔记。

先运行与 Context 裁剪和交互命令相关的快速测试：

```powershell
python -X utf8 -m pytest -q test_main_result_semantics.py tests\test_agent.py test_terminal_output_labels.py
```

## 6. 第二步：交互模式

使用 Kimi K3：

```powershell
python -X utf8 .\main.py --mode interactive --provider kimi --model kimi-k3
```

使用 DeepSeek：

```powershell
python -X utf8 .\main.py --mode interactive --provider deepseek
```

交互提示符中支持：

| 命令 | 作用 | 是否请求模型 |
|---|---|---:|
| `status` | 显示当前 Provider、模型、模式和历史长度 | 否 |
| `modes` | 显示可用模式 | 否 |
| `mode no_history` | 切换当前模式 | 否 |
| `modes no_history` | 兼容写法，切换当前模式 | 否 |
| `samples` | 显示中文示例任务 | 否 |
| `clear` | 清空交互历史 | 否 |
| `quit` / `exit` | 退出 | 否 |
| 普通文本 | 交给 Agent 执行 | 是 |

最小 History 验证：

```text
status
请记住标记 CONTEXT-47，只回复“已记住”。
刚才需要记住的标记是什么？只回复标记本身。
status
quit
```

只有两条普通文本会请求模型；`status` 和模式命令不应出现 HTTP 请求日志。

## 7. 第三步：单任务运行

```powershell
python -X utf8 .\main.py `
  --mode single `
  --provider kimi `
  --model kimi-k3 `
  --context-mode full `
  --task '把 1000 美元换算成欧元、英镑、日元并求平均值' `
  --output '.\outputs\context-single.json'
```

预期终端输出至少包含：

```text
【执行轮次】
【模型请求】
【模型响应】
【工具调用】或【最终回答】
```

`--output` 保存单任务 JSON；它不是正式实验的 `evidence.json`。

## 8. 第四步：逐个模式探测

每条命令都会请求模型。建议先跑 `full`，读懂 evidence 后再运行其他模式，不要并行执行。

```powershell
$base = '.\outputs'

python -X utf8 .\run_experiment_1_1.py --provider kimi --model kimi-k3 --modes full            --task guarded --hidden-result empty --max-iterations 3 --output-dir "$base\context-study-full"
python -X utf8 .\run_experiment_1_1.py --provider kimi --model kimi-k3 --modes no_history      --task guarded --hidden-result empty --max-iterations 3 --output-dir "$base\context-study-no-history"
python -X utf8 .\run_experiment_1_1.py --provider kimi --model kimi-k3 --modes no_tool_results --task guarded --hidden-result empty --max-iterations 3 --output-dir "$base\context-study-no-tool-results"
python -X utf8 .\run_experiment_1_1.py --provider kimi --model kimi-k3 --modes no_tool_calls   --task guarded --hidden-result empty --max-iterations 3 --output-dir "$base\context-study-no-tool-calls"
python -X utf8 .\run_experiment_1_1.py --provider kimi --model kimi-k3 --modes no_reasoning    --task guarded --hidden-result empty --max-iterations 3 --output-dir "$base\context-study-no-reasoning"
```

只指定一个或部分 `--modes` 属于探测运行，不会更新 `validation/latest.json`。

## 9. 第五步：完整五模式正式实验

不传 `--modes` 即运行全部五种模式：

```powershell
$runDir = '.\outputs\context-1-1-my-full-run'

python -X utf8 .\run_experiment_1_1.py `
  --provider kimi `
  --model kimi-k3 `
  --task guarded `
  --hidden-result empty `
  --max-iterations 5 `
  --output-dir $runDir
```

标准配置要求：

```text
task = guarded
hidden-result = empty
modes = 全部五种
max-iterations >= 2
```

输出目录应包含：

```text
evidence.json
evidence.sha256
```

只有完整标准配置且验收通过时，结果才可能更新仓库内 `validation/latest.json`。

## 10. 读取与核验 evidence

```powershell
$evidencePath = Join-Path $runDir 'evidence.json'
$shaPath = Join-Path $runDir 'evidence.sha256'
$evidence = Get-Content -LiteralPath $evidencePath -Raw | ConvertFrom-Json

$evidence.acceptance | Format-List
$evidence.arms | Select-Object mode,completed,task_success,outcome,iterations,repeated_tool_calls | Format-Table
Get-Content -LiteralPath $shaPath
```

读取单个模式：

```powershell
$arm = @($evidence.arms) | Where-Object mode -eq 'full'
$arm.context_contract | Format-List
$arm.behavior | Format-List
$arm.tool_call_signatures
$arm.context_contract.request_roles
```

建议按以下顺序检查：

1. `acceptance.passed`：整组实验是否通过验收；
2. `context_contract.passed`：实际请求是否满足对应裁剪规则；
3. `request_roles`：模型每轮实际看到哪些消息角色；
4. `tool_call_signatures`：工具行动是否重复；
5. `completed`、`task_success`、`outcome`：是否完成且正确；
6. `groundedness`：关键数字是否来自模型可见 Observation；
7. `api_turns` 和 Provider Response ID：是否有真实请求证据。

校验 SHA-256：

```powershell
$expected = ((Get-Content -LiteralPath $shaPath -Raw) -split '\s+')[0].ToLower()
$actual = (Get-FileHash -LiteralPath $evidencePath -Algorithm SHA256).Hash.ToLower()
"【SHA-256】匹配：$($expected -eq $actual)"
```

SHA 匹配只证明当前 JSON 与当前 sidecar 一致，不等于 Provider 对内容进行了签名。

## 13. 常见故障

### 模式命令触发了模型请求

正确写法是：

```text
mode no_history
```

也兼容：

```text
modes no_history
```

当前实现中它们都应在交互命令分流阶段完成，不进入 `execute_task()`。若仍出现 HTTP 请求，先确认运行的是当前目录中的 `main.py`。

### Provider 与模型不匹配

优先只指定 Provider，让注册表选择默认模型：

```powershell
python -X utf8 .\main.py --mode interactive --provider deepseek
```

不要给 `deepseek` 传 `kimi-k3`，也不要给 `moonshot` 传 DeepSeek 模型 ID。

### 429、超时或连接失败

先区分 Provider 故障与 Context 模式结果：

1. 检查终端最早出现的 HTTP 状态；
2. 检查 evidence 中 `api_turns.error`；
3. 不并行运行多个真实实验；
4. 429 或超时不能当成某个 Context 模式导致的退化。

### 达到最大轮次

先查看是否重复调用相同工具，再决定是否增大 `--max-iterations`。不要只为获得一个最终文本而无限提高轮次。

### evidence 与 `latest.json` 不一致

以本次 `--output-dir` 中的 `evidence.json` 为准。`validation/latest.json` 是仓库台账，不是所有个人探测运行的别名。
