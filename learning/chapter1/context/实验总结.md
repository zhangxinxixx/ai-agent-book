## 三、各分支实测表现与行为分析

### 1. `full`：保留完整上下文（对照组）

#### 实测输出与行为分析
```text
Mode                  : full
Completed             : True
Outcome               : correct
Iterations            : 3
ToolActionCount       : 4
RepeatedToolAction    : False
ContextContractPassed : True
Groundedness          : not_assessable

Tool call signatures:
convert_currency:{"amount": 2100000, "from_currency": "EUR", "to_currency": "USD"}
convert_currency:{"amount": 1800000, "from_currency": "GBP", "to_currency": "USD"}
convert_currency:{"amount": 380000000, "from_currency": "JPY", "to_currency": "USD"}
code_interpreter:{"code": "q1_usd = 2500000.00\nq2_usd = 2282608.70\nq3_usd = 2278481.01\nq4_usd = 2541806.02\nquarters = [q1_usd, q2_usd, q3_usd, q4_usd]\nannual_total = sum(quarters)\nquarterly_average = annual_total /4\nprint(f\"Annual total: ${annual_total:,.2f}\")\nprint(f\"Quarterly average: ${quarterly_average:,.2f}\")"}

Request roles by turn:
turn 1: system -> user
turn 2: system -> user -> assistant -> tool -> tool -> tool
turn 3: system -> user -> assistant -> tool -> tool -> tool -> assistant -> tool
```
- **原因**：第 1 轮同时发起 3 笔换汇；第 2 轮读取工具返回的真实数字，并用 Python 精确求和；第 3 轮给出最终答案。每一轮都能看到前面的消息，所以任务顺利完成。

### 2. `no_history`：不保留前几轮消息

#### 实测输出与行为分析
```text
Mode                  : no_history
Completed             : False
Outcome               : no_terminal_response
Iterations            : 3
ToolActionCount       : 9
RepeatedToolAction    : True
ContextContractPassed : True
Groundedness          : no_answer

Request roles by turn:
turn 1: system -> user
turn 2: system -> user
turn 3: system -> user
```
- **原因**：[`_prepare_messages_for_api`](code/agent.py#L681) 每一轮都会清空历史，只留下 `system -> user`。模型每次都以为任务刚开始，于是连续 3 轮重复相同的 3 次换汇，共调用 9 次工具，始终没有给出最终答案。

---

### 3. `no_tool_results`：不把工具结果告诉模型

#### 实测输出与行为分析
```text
Mode                  : no_tool_results
Completed             : False
Outcome               : no_terminal_response
Iterations            : 3
ToolActionCount       : 5
RepeatedToolAction    : True
ContextContractPassed : True
Groundedness          : no_answer

Tool call signatures:
1. convert_currency:{"amount": 2100000, "from_currency": "EUR", "to_currency": "USD"}
2. convert_currency:{"amount": 1800000, "from_currency": "GBP", "to_currency": "USD"}
3. convert_currency:{"amount": 380000000, "from_currency": "JPY", "to_currency": "USD"}
4. convert_currency:{"amount": 2100000, "from_currency": "EUR", "to_currency": "USD"}
5. convert_currency:{"amount": 1, "from_currency": "EUR", "to_currency": "USD"}
```
- **原因**：历史消息还在，但 [`agent.py:893`](code/agent.py#L893) 隐藏了工具结果（`tool_results_hidden: True`）。模型看不到换汇数字，只能再次调用工具，后来又尝试查询“1 欧元的汇率”。因为新结果仍然看不到，最终没有完成任务。

### 4. `no_tool_calls`：不向模型提供工具

#### 实测输出与行为分析
```text
Mode                  : no_tool_calls
Completed             : True
Outcome               : unsupported_numbers
Iterations            : 1
ToolActionCount       : 0
RepeatedToolAction    : False
ContextContractPassed : True
Groundedness          : ungrounded
```
- **原因**：请求中没有工具定义（`tools_absent_every_turn: True`），模型却直接给出了金额。虽然它生成了一段完整回答（`Completed: True`），但 [grounding.py:assess_groundedness](code/grounding.py#L125) 发现这些数字都没有工具结果作为依据，因此判定为**无依据数字（`unsupported_numbers`）**。

---

### 5. `no_reasoning`：剥离思维链/思考过程（对比分析）

这个模式运行了两次，结果一次正确、一次错误，说明删掉推理记录后表现不稳定：

#### 运行 1：偶发正确
- **实测表现**：`Completed: True`, `Outcome: correct`
- **原因**：这次模型把完整金额（`2100000`, `1800000`, `380000000`）正确传给工具。工具返回的真实数字（如 `2282608.70`）提供了清楚的中间结果，所以即使不保留推理记录，最后仍然算对了。

#### 运行 2：单位混淆导致错误
- **实测表现**：`Completed: True`, **`Outcome: incorrect`**
- **实测工具签名**：
  ```text
  convert_currency:{"amount": 2.1, "from_currency": "EUR", "to_currency": "USD"}
  convert_currency:{"amount": 1.8, "from_currency": "GBP", "to_currency": "USD"}
  convert_currency:{"amount": 380, "from_currency": "JPY", "to_currency": "USD"}
  code_interpreter:{"code": "q1 = 2.50\nq2= 2.28\nq3 = 2.28\nq4 = 2.54\n...\nprint(f\"Annual total:  {total:.2f} million USD\")"}
  ```
- **成因剖析**：
  1. **单位尺度混淆**：任务原要求 3.8 亿日元（380 million JPY），模型脱离思维链后将 `amount` 传成了 `380` 单个日元；
  2. **精度截断未达标**：Python 脚本输出了概数 `9.60 million USD`，未能命中 [run_experiment_1_1.py:41](code/run_experiment_1_1.py#L41) 要求的基准全量数字 `EXPECTED_NUMBERS = ("9602895.73", "2400723.93")`；
  3. **结果对照**：该次运行被记录为 `incorrect`，与行为分析一致。

## 四、从实验中得到的工程建议

1. **生成了回答，不代表回答正确**：
   只看 `Completed: True`，会把 `no_tool_calls` 中没有数据依据的回答误判为成功。还要检查答案中的数字能不能在工具结果中找到来源。
2. **工具结果是模型继续行动的依据**：
   `no_history` 中，模型因为看不到前几轮消息而重复操作；`no_tool_results` 中，模型因为看不到工具结果而不断重试。模型必须拿到前面的事实，才能正确决定下一步。
3. **推理记录能帮助模型保持单位和步骤一致**：
   `no_reasoning` 的两次结果说明：即使工具正常工作，模型也可能把“百万”误当成普通个位数，或者过早截断小数。推理记录能帮助模型在多轮任务中保持单位和计算步骤一致。
4. **实验必须留下可以检查的记录**：
   应记录每轮实际发送的消息、工具输入输出和最终判定。这样才能确认模式真的生效，也能在结果异常时找到原因。
