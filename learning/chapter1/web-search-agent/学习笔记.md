# Chapter 1：Web Search Agent 学习笔记

> 学习目标：理解一个搜索 Agent 怎样把模型的决定、工具执行结果和下一轮上下文连成可持续的反馈循环。

## 1. 什么是 AI Agent

AI Agent 不是单独调用一次大模型，而是让模型在一个受控制的循环中，根据当前信息决定下一步行动，再利用行动结果继续判断。

本项目可以用下面的框架理解：

```text
Agent = LLM + Context + Tools
```

| 部分 | 在本项目中的作用 |
| --- | --- |
| LLM | Kimi 根据当前问题和已有搜索结果，决定是否继续调用 `web_search`，以及搜索什么 |
| Context | `conversation_history` 保存用户问题、模型的 Tool Call 和工具返回结果，作为下一轮输入 |
| Tools | Moonshot Formula 提供 `web_search` 工具声明，并通过 Fiber 真正执行搜索 |

工程实现中还需要 Python Harness，也就是 `WebSearchAgent`：它负责维护消息、调用模型、执行工具、回填结果、控制最大轮次和处理错误。模型负责“决定做什么”，Harness 负责“真正执行并维护循环”。

## 2. 一次搜索任务怎样运行

```text
用户提出问题
→ Harness 建立 system + user 消息
→ 模型读取 messages + tools
→ 模型返回 web_search Tool Call
→ Harness 调用 Formula Fiber 执行搜索
→ 搜索结果写成 role=tool 消息
→ 模型读取更新后的 Context 再次决定
→ 继续搜索，或返回最终答案
```

这个循环最关键的部分不是“调用了搜索”，而是工具结果必须重新写回模型能够看到的 Context。否则模型虽然执行过工具，下一轮却不知道工具返回了什么。

## 3. State、Action、Observation 对应什么

| Agent 抽象 | 本项目中的真实对象 |
| --- | --- |
| State | `conversation_history` |
| Action | 模型生成的 `web_search` Tool Call，包括 `id`、`name` 和 `arguments` |
| Observation | Formula 返回的搜索结果，经处理后写入 `role=tool` 消息 |
| Decision | 模型根据当前 Context 决定继续搜索还是输出答案 |
| Guard | `max_iterations`、请求超时、`finish_reason` 和错误处理 |
| Verifier | `run_experiment_1_2.py::validate()` 对运行证据进行验收 |

一次模型响应可能包含多个 Tool Call，所以一次 iteration 不一定只执行一次搜索。Harness 会执行本轮全部 Tool Call、逐条回填结果，然后才发起下一轮模型请求。

## 4. 三类状态不要混淆

| 状态 | 真实变量 | 用途 |
| --- | --- | --- |
| 模型可见状态 | `conversation_history` | 下一轮真正发送给模型的消息 |
| 展示轨迹 | `trace` | 供学习者查看 thought、action、observation 和 answer |
| API 证据 | `api_turns` | 保存工具声明、Chat Completion 和 Formula Fiber 的请求结果，供排障与验收 |

`trace` 中出现了 Observation，不代表模型一定看到了它。只有对应结果进入 `conversation_history` 的 `role=tool` 消息，才会影响下一轮决策。

每次调用 `search_and_answer()` 都会重新初始化这三类状态。因此命令行交互模式虽然可以连续输入问题，但默认不是跨问题保留记忆的长期对话。

## 5. 最容易理解错的边界

1. `_get_tools()` 获取的是工具说明书，不是搜索结果；真正的搜索发生在 `_execute_formula()`。
2. `_chat()` 只向模型请求下一步决定，不会自己执行工具。
3. Assistant Tool Call 表示 Action，`role=tool` 表示 Observation，两者通过 `tool_call_id` 配对。
4. 模型不再返回 Tool Call 并给出文本，是 Soft Stop；达到最大轮次是 Harness 的 Hard Stop。
5. 有最终答案不等于实验通过，还要检查真实 Formula 回执、来源和 `acceptance.passed`。
6. OpenRouter 兜底分支没有 Moonshot Formula 工具链，不能作为实验 1-2 的真实搜索证据。

## 6. 当前属于哪种实验

当前项目主要用于观察完整 Agent Loop，属于“机制观察”，不是严格的对照实验。本轮没有主动操纵独立变量；每轮 Search Result 是运行过程中变化的新输入，不能自动当作实验自变量。

如果要做真正的对照，可以固定模型、问题和轮次，只改变“是否把工具结果写回 Context”，再比较下一轮 Query、重复搜索次数、停止方式和最终答案是否有依据。

## 8. 我对 Agent 的理解（打卡版）

我理解的 AI Agent 不是一个只负责回答问题的大模型，而是由 LLM、Context 和 Tools 组成的反馈系统。LLM 根据当前上下文决定下一步做什么；Context 保存用户问题、历史行动和工具结果；Tools 负责搜索、计算或访问外部系统。本实验中，Kimi 只生成搜索 Tool Call，Python Harness 才真正调用 Formula Fiber，并把搜索结果作为 `role=tool` 消息写回上下文。模型随后读取新的 Observation，决定继续搜索还是结束。因此，Agent 的关键不是“调用过工具”，而是工具结果能否正确进入下一轮决策，同时还要用轮次、超时和验收规则限制它的行为。
