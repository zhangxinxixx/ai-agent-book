# 实验 4-4：Execution Tools + MCP 学习笔记

![执行工具静态架构图](assets/执行工具静态架构图.png)

## 1. 为什么 Agent 需要 Tools

LLM 擅长理解问题和生成文本，但它不能只靠“想”就修改文件、执行代码或调用外部系统。Tool 的作用，是把模型给出的意图转换成一次可检查、可执行、可返回结果的动作。

```text
LLM 负责判断做什么
Tool 负责在环境里真正执行
Harness 负责校验、路由和记录
```

因此，Agent 不应该直接碰操作系统或第三方服务，而应该通过参数明确、权限受控的 Tool 完成动作。

## 2. Function Calling / Tool Calling 是什么

Function Calling 不是“模型直接运行函数”。模型只生成一个结构化调用请求，例如：

```json
{
  "name": "file_write",
  "arguments": {
    "file_path": "notes/result.txt",
    "content": "done"
  }
}
```

真正执行这个请求的是 Agent Harness 或 MCP Client。它需要先检查工具名和参数，再调用工具，最后把 Tool Result 交回模型。

一次完整流程是：

```text
用户问题
-> LLM 判断是否需要工具
-> LLM 生成 tool_call
-> Harness 校验并执行工具
-> 工具返回结构化结果
-> Harness 把结果作为 Observation 交回 LLM
-> LLM 根据结果组织最终回答
```

注意：当前 `execution-tools` 项目实现的是“校验并执行工具”这一层，没有实现负责自主选工具的 LLM Agent Loop。

## 3. MCP 在这里解决什么问题

MCP 把工具的发现和调用方式统一起来：

- MCP Host：承载 Agent 的应用。
- MCP Client：连接 Server，发送 `tools/list` 和 `tools/call`。
- MCP Server：公开工具 Schema，接收参数并路由到具体实现。

本项目的 `server.py` 是 MCP Server。`handle_list_tools()` 返回工具说明书，`handle_call_tool()` 根据工具名调用 `FileTools`、`ExecutionTools` 等实现，并把结果序列化为 JSON 文本返回。

## 4. 4-4 的核心机制

```text
Action Request
-> Guard
-> Harness Execute
-> Environment Change
-> Result Processing
-> Observation
-> Verifier / Evidence
```

### Guard：执行前拦截风险

- 文件路径必须位于工作区内。
- Python 文件写入前先做语法校验。
- 危险命令需要审批；离线 demo 会直接拒绝。
- 执行过程受 timeout 和资源限制约束。

### Execution：产生真实副作用

- `file_write` / `file_edit` 修改文件。
- `code_interpreter` 执行代码。
- `virtual_terminal` 执行 Shell 命令。
- 扩展工具可连接 Google、GitHub、桌面或移动端环境。

### Observation：把执行结果交还调用者

返回结果不仅有 `success`，还可能包含 `returncode`、`stdout`、`stderr`、`verification` 和完整输出文件路径。长输出会在上下文中截断，同时把完整内容保存到文件，避免占满 Context。

### Verifier：执行后判断证据是否达标

Guard 只回答“能不能执行”，Verifier 回答“执行后是否真的满足目标”。单次 `success=true`、pytest 通过和正式实验 gates 通过是三种不同层级的结论，不能混为一谈。

## 5. 本轮实际运行结果

2026-09-22 在 `agentbook` 环境中执行：

```powershell
conda run -n agentbook python cli.py demo
conda run -n agentbook python -m pytest -q -p no:cacheprovider -o asyncio_mode=auto --basetemp .pytest-tmp
```

观察结果：

- 正常 Python 文件写入成功，`verification=passed`。
- 含语法错误的文件在写入前被 linter 拦截。
- Python 代码执行成功并返回词频统计结果。
- Shell 命令执行成功，返回 `returncode=0`。
- 1000 行输出被截断到上下文摘要，完整内容另存文件。
- 危险命令被本地离线审批器拒绝，未执行、未调用模型。
- 自动测试结果为 `63 passed`。

这次没有调用在线模型或外部服务，也没有证明模型能够自主选择工具。历史 `validation` 只作为旧实验记录，不代表当前源码的实时结果。

## 6. 一句话总结

Execution Tools 的价值不是“能运行命令”，而是把 Tool Call 经过 Guard、安全执行和结果加工，变成可供 Agent 下一轮判断的结构化 Observation。
